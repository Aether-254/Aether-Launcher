# 崩溃分析

游戏起不来或者崩了，启动器自己说清楚原因和下一步。用户不用找文件，也不用看懂日志。能在本地判断的不发出去；要发出去的先脱敏，用户先看到实际内容。

## 流水线

```text
进程退出
  → 采集（本次启动的证据）
  → 本地分类 ── 命中 → 直接给原因和动作
  → 未命中且用户同意
  → 抽取相关段落
  → 第一层脱敏（客户端）→ 预览
  → 窄接口（鉴权、限流、固定 prompt）
  → 第二层脱敏（Cosy 网关）
  → AAPI → 结果
```

编排层（持有实例到进程的状态）负责在进程异常退出或出现新崩溃报告时触发采集。分析逻辑放在纯逻辑的 `aether-diagnose` crate 里：解析、分类、第一层脱敏、payload 组装，不碰网络，用固定样本测试。AAPI 客户端放在 trait 后面，AAPI 不可用时只展示本地分类结果。

## 失败阶段与证据

先判断失败发生在哪个阶段，再决定证据从哪里取。

| 阶段 | 特征 | 证据 |
| --- | --- | --- |
| JVM 没起来 | 进程很快退出，输出很短 | 启动器截到的 stdout/stderr，没有 `latest.log` 更新，也没有崩溃报告 |
| 游戏崩溃 | 本次启动后出现新的 `crash-reports/crash-*.txt` | 崩溃报告，加 `latest.log` 末尾 |
| JVM 原生崩溃 | 出现新的 `hs_err_pid*.log` | `hs_err` 文件 |
| 加载器或启动阶段失败 | 退出码非 0，没有崩溃报告 | `latest.log` 本次新增的部分 |
| 被终止或没有任何输出 | 只有退出码 | 退出码、运行时长 |

stdout/stderr 和 `latest.log` 内容不一样：前者包含 JVM 自己的输出和没进日志框架的异常，后者由 log4j 写，下次启动会被轮转。两个都要采。

**只取本次启动。** 启动前记下 `latest.log` 的长度和各证据目录里最新文件的时间，退出后只取新增的部分。每次启动把证据归档到实例下的 session 目录，保留最近几次，下次启动就不会冲掉。

## 本地分类

很多常见崩溃有固定特征，本地规则直接给出原因，不花 token，也不用把日志发出去。启动器知道的上下文比日志多：选中的 Java、清单版本、加载器和 mod 列表、每个启动参数从哪来。

例子：`Unrecognized option: --sun-misc-unsafe-memory-access=allow`。这个选项随 JDK 23 引入，出现「Unrecognized option」说明实际 Java 比 23 旧。输出本身就是完整的诊断，启动器再补上「这个参数来自哪里、你选的是哪个 Java」。

分类结果带可信度。本地规则命中算高；LLM 的结论要引用它依据的日志行。

**预检用同一张表。** 维护一张「参数 → 最低 Java 版本」的表，启动前就能发现「参数需要的 Java 比选中的新」，不用等崩溃。

## 界面

- 证据已经完整时直接说，例如「这就是全部输出」，不要求用户导出任何东西。
- 不让用户找文件。一个「分析」按钮，一个「导出诊断包」按钮（zip，里面有清单说明包含了什么）。
- 另外提供脱敏后的纯文本摘要，能直接贴到群里或论坛。

## 脱敏

两层。原始日志不离开用户的机器，第二层只当兜底。

**第一层（客户端，`aether-diagnose`）**，负责 MC 特有的信息：

- 启动参数按位置处理：`--accessToken`、`--username`、`--uuid`、`--xuid`、`--clientId` 等
- 路径里的用户名（`C:\Users\<名字>\`、`/home/<名字>/`、`/Users/<名字>/`）
- 玩家名、UUID、IP 和服务器地址、电脑名
- 邮箱，排除 `名字@版本` 形态
- 只抽取需要的段落（异常栈、mod 列表、系统信息），不发整个 `latest.log`

**第二层（[Cosy Redact Gateway](https://github.com/CassiopeiaCode/CosyRedactGateway)）**，部署在服务端，位于窄接口和 AAPI 之间。路由形式是 `/<开关>$<上游 URL>`，开关用 `SIG`：长 `sk-` 密钥、身份证、Gitleaks 兼容规则。

**为什么不用默认的全开。** 在 92 个真实崩溃报告和日志（约 150 万字符，来自 HMCL 的测试资源）上本地评估：

| 检测器 | 结果 |
| --- | --- |
| 邮箱 `E` | 461 次命中，其中 459 次是 `cpw.mods.modlauncher@10.0.8`、`MC-BOOTSTRAP/fmlloader@1.20.1-47.2.16` 这类模块版本串，其余 2 次也是 `mod@版本`；样本里没有真邮箱 |
| 银行卡 `B`、手机号 `P` | 28 次和 3 次，命中的是 `4618424574399199550`、`13423393313` 这类长数字串 |
| 高熵 `H` | 435 次命中，除了 SHA-1/MD5 和十六进制地址，还包括 mod 标识（`micdoodle8`、`xaerobetterpvp`）和贴图尺寸（`512x256x4`） |
| `S`、`I`、`G` | 零命中，没有误伤 |

邮箱和高熵会把加载器版本和 mod 名换成占位符，LLM 就看不到诊断最需要的信息。`SIG` 能挡住 JWT 形态的 `--accessToken`（合成数据测试），但不处理 UUID、玩家名和路径里的用户名，这些由第一层负责。

**预览。** 发送前展示第一层脱敏之后真正要发出去的内容。默认每次询问，选择可以撤销。同意文案要写明：日志会经过 AAPI 到达第三方上游。

## 服务端

不把 AAPI 的 key 放进客户端，客户端也不能自己写 prompt。服务端提供一个窄接口：

- 鉴权用 Aether ID，匿名给很低的额度；限流和 token 上限在服务端。
- 输入是结构化的崩溃报告，system prompt、模型选择都在服务端。
- 输出是结构化的：原因、依据的日志行、建议动作、可信度。建议动作限定为启动器认识的几种（换 Java、加内存、禁用某个 mod 等），每一步都要用户确认。
- Cosy 本身不认证调用者，所以认证放在它前面，不把 Cosy 地址直接给客户端。

**日志是不可信输入。** 里面有 mod、服务器和聊天写进去的文本，可以做提示词注入。模型输出只当建议，渲染成纯文本，不自动执行。

**缓存。** 对异常类、栈顶几帧和相关 mod 集合做归一化哈希，AAPI 侧按这个签名缓存分析结果，只存签名和结果，不存原始日志。Cosy 的占位符只在单个请求内可还原，所以缓存 key 用结构化签名而不是脱敏后的文本，写缓存前去掉结果里的占位符，prompt 要求模型不要原样引用被脱敏的值。

## 待定

- 「参数 → 最低 Java 版本」表的来源和维护方式。目前只核实了 `--sun-misc-unsafe-memory-access`（JDK 23）。
- 诊断包的格式，以及 session 目录保留几次。
- 固定样本的来源。评估用的 HMCL 样本是 GPL，不收录进本仓库，需要自己收集有授权的样本。
- 匿名额度的具体数值。
